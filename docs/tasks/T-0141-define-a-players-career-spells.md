## Goal

A player record can carry the clubs they played for, with years, games and
goals (ADR 0009 D2). Every learning feature in ADR 0009 reads this field.

## Context

- ADR 0009 D2, ADR 0005 D4, D7 and D9 (field names, facts with a source,
  adding an optional field to `v1`).
- `player.schema.json` already has `clubGoalCount`, a fact object. Use the
  same fact shape for the counts.
- `src/player-card-fields.test.ts` shows how the package tests a field.

## Acceptance criteria

- `player.schema.json` has an optional `careerSpells` array. Each item has
  `club` (pattern `^clubs/[a-z][a-z0-9-]{0,62}$`, required), `startYear`
  (required), `endYear`, `appearanceCount` and `goalCount`. The counts use
  the existing fact shape with `sourceUri` and `retrieveDate`.
- Years are whole numbers from 1850 to 2100. An item allows no other
  property.
- The field's description says the list is oldest first and leaves out
  youth and reserve sides.
- One example in `schemas/v1/examples/` has career spells, one of them
  current (no `endYear`).
- The generated types are regenerated by the package's own command, not by
  hand.
- The design lint passes on the new field.
- `make check COMPONENT=schema` passes.

## Edge cases

- `endYear` earlier than `startYear`: the schema can't express it, so the
  test documents that the pipeline must refuse it (T-0142).
- A spell with no counts: valid.
- An empty `careerSpells` list: refused (`minItems: 1`). An unknown career
  is an absent field.

## Tests

- `src/career-spells.test.ts`: a valid record with spells passes. A bad
  club name, a year out of range, an extra property, a count given as a
  bare number and an empty list each fail.

## Out of scope

- The pipeline (T-0142), the site and club colours.
